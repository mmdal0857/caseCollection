**v2 (플레이 반응 반영)**: ①슬롯별 반응 피드백 — 엉뚱한 카드엔 탐정 플레이버·코믹 반응
(예: 독물 흔적을 침입 경로에 → "독이 제 발로 문을 열고 들어왔다는 건가?"), 정답엔 확정 플레이버.
②인터루드 조사 미니루프 — 리드를 짚어 다음 사건 배경·힌트를 "찾아가는" 과정 + 다음 사건 예고.
③게스트/내 단서 UI 분리("빌린 단서 — 해결 시 영구 획득"). ④슈트 아이콘 자리표시자(실아트는 티켓 13).

**v3 (드라마투르기 패턴화)**: 손수 개그 대신 오답을 "왜 틀렸나"의 구조로 분류·생성.
카드에 `kind`(사람·사물·행위·기록·현상), 슬롯에 `frame`(route·means·trace…) → `dramaturgy.ts`가
kind×frame 부조화를 코믹 패턴(범주 오류·행위자 오귀속·문자적 과장·정반대…)으로 매핑·생성.
우선순위: 감독판(손수) > 정답 hit > 패턴 생성 > 슈트 폴백. 패턴명을 UI 태그로 노출.

**v4 (시나리오 보드 — 위치·인접 시너지)**: 상단 토글로 진입하는 **별도 모드**.
카드를 나란히 배치하면 인접쌍이 kind 인과 사슬(사람→행위→흔적→기록)을 따라 **서사 링크**를 맺고,
잘 엮으면 아래에 **사건 시나리오가 조립**되고 비약하면 코믹하게 깨진다("종이 쪼가리가 사람을 부린 겐가").
"정답 맞히기"가 아니라 "앞뒤 맞는 이야기 짓기" — 새 게임 스타일 탐색(`scenario.ts`).

**v5 (캐릭터 유머 + 시나리오 보드 확장성·재확인성)**: ①`persona.ts` — 레이든 페르소나 층,
어이없는 배치에 그의 몸짓 부착("레이든은 관자놀이를 눌렀다. 이런 조수는 처음이었다"). ②시나리오 보드
링크가 다중 신호(kind 인과 + **태그 공명** → '강한 인과✦'). ③**재확인(검토)** 버튼 — 조립한 시나리오를
진실 골격(범인→범행→흔적→증거)에 대조해 **성립/미흡/반증** 판정 + 약한 고리 지목(조립→검토→수정 루프).

**v6 (통합 1차 — 시나리오 조립을 추리 보드에 흡수)**: 리서치 결론(Golden Idol식 빈칸 두루마리)대로,
시나리오 보드를 별도 모드가 아니라 **추리 보드 자체**에 흡수. "추리 게임 (통합)" 모드에서 슬롯을 채우면
**정답 축**(근접도+3확정)과 **서사 축**(서사 사슬 인접 링크·응집도·재확인)이 한 보드에서 나란히 작동.
시나리오 보드는 "시나리오 샌드박스"로 강등.

**v7 (정답 = 앞뒤 맞는 이야기 정렬)**: 서사 응집도를 kind-rank(과엄격)에서 **역할 적합도**로 재설계 —
`cardFitsSlot`(카드 kind가 슬롯 역할이 받는 kind면 맞음). 정답 카드는 자기 역할에 맞으므로 **정답=응집 full**.
검증: case1 정답 배치 → 응집 3/3(강한 링크⇒ 포함), 잘못된 kind 카드 → 빨간 misfit 노드+링크 끊김+재확인이
약한 고리 지목. 두 축(정답 근접도 + 서사 응집)이 정렬 — 응집이 정답을 guide, 근접도가 THE 카드 확정.

**v8 (태그 = 영역 다수결, Tigris 오마쥬)**: 문맥 태그 시스템을 **영향력 줄다리기**로 가시화.
①메터에 두 극(주목=은밀◁▷공개, 신뢰=강압◁▷신중)과 우세 극·다수결 임계 표시. ②확정 시 **영향력 노트**
("논리×1 공개×2 → 주목 +2") — 어떤 태그가 트랙을 밀었는지. ③임계를 넘으면 **규집 배너** —
"[결정적 증거]의 정답이 지금 다른 카드로 바뀌어 있다". 다수 극이 판정 규칙을 쥔다는 게 눈에 보인다.

**v9 (템포·행동 경제, Dune: Imperium 오마쥬 + 클리어 피드백 수정)**: 인터루드가 **AP 배분 퍼즐**로.
행동력 3을 조사 리드(각 1)와 행동 4종(보고서 정리 1 / 소문 잠재우기 2 / 정보원 매수 2 / 감식반 요청 3)에
배분 — **전부는 못 한다**. 서사 선택지는 무료(이야기 비트). 또 클리어 시 즉시 보상으로 튀던 걸 고쳐,
반응·영향력 노트를 보여준 뒤 **"계속"**으로 넘어간다. → 리서치 톱5 메커닉 전부 프로토 구현 완료.

**v10 (얼굴 의미론 — 티켓 12를 판 위에 올림)**: 카드 태그가 "비용표"에서 **"이 카드가 무엇이 될 수 있는지의 목록"**으로.
①카드마다 **얼굴(facet) 2~3개** — 실·섬유가 [침입 도구]·[접촉 증거]·[신분의 실마리]. 슬롯에 놓을 때 **어떤 얼굴로 읽을지 고른다**
(그게 곧 수). ②**이웃이 의미를 만든다** — 얼굴마다 `needsPrev`: 앞 슬롯이 [연출된 현장]으로 잠겨야 "연습된 진술"을 [신분 위장]으로
읽을 수 있다. ③**배경 상태가 게이트** — 너무 조용하면 요란한 해석이, 너무 신중하면 거친 해석이 잠긴다(안전한 구석 없음).
④**보유 ≠ 앎** — 카드를 얻으면 얼굴 하나만 안다. 게스트가 얼굴을 빌려주고, **강한 링크(태그 공명)**로 새 얼굴을 발견한다.
⑤얼굴 태그가 트랙을 민다(오답 플랫 페널티 제거 — 오답도 세계를 미는 수). ⑥**case별 가변축**(봉인·시간·증언 일관성·인적).
⑦수사 노트에 **오답 해석도 줄 그어진 채** 남는다.

> **★ 잠금 시점 토글 — 이 프로토의 1번 질문.** 화면 상단에서 세 모드를 바꿔가며 같은 사건을 플레이한다:
> **즉시 잠금**(12 §3의 제안 — 놓으면 확정, 되돌리면 주목+1 및 뒤가 연쇄 해제) /
> **가늠 → 확정**(절충안 — 놓는 건 자유, [확정]을 눌러야 잠기고 전파) /
> **제출 시 잠금**(11 v6의 판단 — 제출 전까지 전부 유동, 옮길 때마다 실시간 재해석).
> 11은 "배치 중 라이브 재해석이 재미 그 자체"라 봤고 12는 즉시 잠금으로 갔다 — **이 둘이 정면충돌한다.**
> 판을 갈아엎지 않고 시점만 바뀌므로 한 사건 안에서 직접 비교할 수 있다.

- `src/lib/facets.ts` — **v10 순수 모듈**. 얼굴의 합법성만 판정(모르는 얼굴 / 상태 게이트 / 앞 문맥)
  + 해석 공간 계산. UI·상태 저장 없음 — 콘텐츠 검증기로 승격될 후보.
- `src/lib/engine.ts` — **순수 리듀서** (UI 비의존). 어휘 게이트, 근접도+3개 단위 확정,
  가설 선언, 배경 상태(주목·신뢰)와 문맥 조건부 정답, 인터루드/BAD 평가, 수사 노트 해금.
  검증되면 이 모듈만 실제 코드로 승격 가능.
- `src/lib/content.ts` — 수제 시드 콘텐츠 (솔버빌리티 수제 튜닝 — 팩 선택과 무관하게 전 case 해결 가능).
- `src/App.svelte` + `src/lib/ui/` — 던지는 셸. juice는 전부 Svelte 내장만 사용
  (crossfade 카드 이동, FLIP 손 정렬, 오답 shake, 확정 flip, 미터 tween, 화면 전환).

## 플레이하며 판정할 것 — v10 (티켓 17의 검증 항목)

1. **★ 즉시 잠금이 포석의 재미인가, 실험을 막는 답답함인가** — 세 모드를 바꿔가며 같은 사건을 풀어볼 것.
   즉시 잠금에서 "약한 카드를 먼저 깔아 뒤를 연다"는 포석이 실제로 성립하는가, 아니면 그냥 손이 묶이는가.
2. **얼굴 다면성** — 한 카드에 용도가 여럿인 게 발견인가, "뭐가 뭔지 모르겠다"인가. 2개 vs 3개 중 어느 쪽이 맞는가.
3. **보유 ≠ 앎** — 가진 카드의 얼굴을 못 쓰는 게 성장감인가 답답함인가. 게스트 대여가 완충으로 충분한가.
4. **앞→뒤 단방향 + 연쇄 해제** — 앞을 고치면 뒤가 다 풀리는 게 긴장인가 좌절인가. 되돌리기 비용(주목 +1)이 적정한가.
5. **가변축** — case마다 다른 축이 리플레이성인가, 매번 새 규칙을 배우는 부담인가.
6. **등급형 실패 + 얼굴 잠김** — 조용히 가면 안 죽지만 해석이 마르는 게 체감되는가.
7. **오답도 노트에** — 줄 그어진 오답 해석이 "부끄러운 자산"인가 잡동사니인가.

### 기계 검증은 이미 돌려놨다 (`node smoke.mjs`)

`npx esbuild smoke.ts --bundle --format=esm --platform=node --outfile=smoke.mjs && node smoke.mjs`

| 항목 | 결과 |
|---|---|
| A. 잠금 모드 3종 완주 (즉시 잠금이 소프트락을 만드는가) | **PASS** — 3종 모두 GOOD 완주 |
| B. 콘텐츠 검증기 — 4개 case 이중 제약(①아는 얼굴만으로 풀림 + ②이야기로 성립) | **PASS** — 응집 전부 full |
| C. 죽는 방향 둘 (공개 과다 → 언론 재판 / 강압 과다 → 수사반 붕괴) | **PASS** — 둘 다 도달 가능 |
| E. 이웃이 의미를 만든다 (앞을 잠그면 뒤가 열림) | **PASS** |
| D. 되돌리기 연쇄 해제 + 대가 | **PASS** |

**C는 처음엔 FAIL이었다 — 실제 발견**: 초안에서는 강압 얼굴 5개가 전부 `facets[1+]`에 있어 학습기에는
**고를 수조차 없었다**(어휘 게이트 §4와 실패 설계 §7의 충돌 — "죽는 방향 둘"이 초반엔 사실상 하나).
수정: 강압 얼굴 하나(밧줄 마찰 자국 [구속의 도구])를 명백한 얼굴(`facets[0]`)로 승격해 해소.
→ **일반 규칙 후보: 콘텐츠 검증기에 "각 실패 방향은 스타터 어휘만으로 도달 가능해야 한다" 제약 추가**(12 재개정 후보).

## 플레이하며 판정할 것 (티켓 11의 검증 항목 — 완료)

1. **어휘 게이트 퍼즐** — 슬롯 채우기 + "몇 개 맞음" + 3개 단위 확정이 긴장·진전감을 주는가
2. **문맥 태그 체감** — 주목 5+에서 정답이 바뀌는 구조(case 2·3·보스)가 "배울 수 있다"고 느껴지는가, 자의적인가
3. **런 긴장감** — 주목/신뢰 관리·인터루드·BAD 리스크가 카드 선택에 전략적 무게를 싣는가
4. **DOM juice 충분성** — Svelte 내장 연출만으로 타격감이 충분한가 (부족하면 PixiJS 해치 발동 → 05 결정 반영)
5. **가설 선언** — 패턴 선언(적중 시 슈트별 근접도)이 추리에 재미를 더하는가
6. **수사 노트 해금** — 확정된 카드의 의미 텍스트가 열리는 것이 동기 부여가 되는가

BAD 엔딩도 한 번은 일부러 밟아볼 것 (오답을 여러 번 내거나 [공개] 태그 카드를 많이 확정하면 주목이 오른다).
