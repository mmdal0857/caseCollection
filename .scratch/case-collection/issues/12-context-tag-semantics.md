## Question

[코어 루프 확정](03-core-loop.md)의 독창 메커닉 — 문맥 태그 시스템 — 의 세부 설계. 배경 상태의 변수 집합(무엇이 상태인가), 태그×상태 조합식의 형태(평가 규칙을 빌드타임 생성이 만들 수 있는 표현으로), 오답이 일으키는 상태 오염의 종류, 인터루드 이벤트의 트리거 테이블과 BAD 엔딩 비중을 확정한다. 위키의 정성 데이터(trope_tags, clue 카테고리, 인물 문자열)가 태그의 원천이 될 수 있는지 매핑 포함. ## Comments

- 2026-07-20 **프로토(11) v1~v9 완주 + [03 재개정](03-core-loop.md)으로 입력 준비 완료** — 이제 그릴링 가능. 프로토가 제공하는 구체 근거:
  - **뼈대 후보 = 영역 다수결**(v8, Tigris 오마쥬): 배경 상태를 **두 극의 줄다리기 트랙**으로 — 주목 = 은밀 ◁▷ 공개, 신뢰 = 강압 ◁▷ 신중. 확정 카드의 태그가 영향력을 놓고, **다수결 임계를 넘으면 판정 규칙이 flip**(같은 슬롯, 다른 답). 임계 초과로 인터루드를 맞으면 BAD.
  - **의미 어휘 = kind × frame**(v3~v7): 카드 `kind`(사람·사물·행위·기록·현상) × 슬롯 `frame`(route·means·trace·action·motive·record·omission·scene·identity). 이 조합이 코믹 반응 생성·서사 응집·정답 정렬을 동시에 지탱 — **조합식의 유력한 표현형**(빌드타임 생성이 다룰 수 있는 이산 매핑).
  - **미확정 쟁점(그릴링 대상)**: ①**영향력 타이밍** — 현재 프로토는 *확정된(정답) 카드만* 트랙에 영향. "쓴 카드 전부 영향" vs "정답만"은 게임 성격을 가른다(전자는 스테이크가 커지고 후자는 실력이 곧 안전). ②태그 세트가 5종(공개·은밀·강압·신중·논리)으로 충분한가 / 위키 trope_tags 매핑 경로. ③상태 오염의 종류(현재는 오답 제출 +주목 단일) ④인터루드 트리거 테이블과 BAD 비중 ⑤조합식이 case 생성기가 만들 수 있는 형태인가([03] 이중 제약과 정합).
  - 프로토 관찰: "깔끔한 해결이 주목을 냉각시킨다"(정답의 은밀 태그가 주목을 낮춤) — BAD가 잘 안 뜨는 밸런스 위험 vs "실력이 곧 안전"이라는 Koster 정합, ①과 직결되는 판단.
