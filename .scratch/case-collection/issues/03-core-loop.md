# 코어 루프 확정

Status: closed
Labels: wayfinder:grilling
Assignee: MMDAL (fable session, 2026-07-19)
Blocked-by: 01, 02

## Question

caseCollection의 코어 루프는 무엇인가 — 플레이어가 반복하는 학습 가능한 시스템(Koster), 한 세션의 형태, 카드 획득 방식(플레이로 획득)과 수집물의 게임적 사용이 맞물리는 구조. [메커닉 설계 공간 서베이](01-mechanic-survey.md)의 후보 패턴과 [위키 데이터 인벤토리](02-wiki-data-inventory.md)의 실제 데이터 형태를 재료로 결정한다. 후보 루프가 좁혀지면 /prototype으로 페이퍼/코드 프로토타입을 만들어 비교한 뒤 확정.

## Resolution

2026-07-19, 그릴링 세션(MMDAL × Fable). 종이 위 확정 — 재미 검증은 [코어 루프 프로토타입](11-core-loop-prototype.md)에서, 반증 시 이 결정을 재개정한다.

- **루프 가족**: ⓑ 수집=퍼즐재료(Golden Idol형)로 MVP → 재미 검증 후 ⓐ 단서-투-덱(× StS) 확장. 서베이 권고 수용.
- **case** (핵심 명사, "case" 재정의 채택 — `CONTEXT.md` 기록): 빌드타임 생성된 사건 퍼즐 1판. case_pattern 4종이 골격, story 77의 인물·범죄유형·트롭이 소재풀. 원작 근거는 소재풀 경유로 유지, 변주 공간은 4×77로 확대.
- **수집×플레이 (C면)**: 어휘 게이트 — 추리 슬롯엔 보유 단서 카드만 사용 가능. case 생성이 플레이어 컬렉션 기반이라 "못 푸는 판" 문제 차단. + 소모형 힌트 카드(순간 전술).
- **획득 (B면)**: 게스트 단서 학습형(case 내 임시 사용 → 클리어 시 영구 획득) + 보상팩 혼용, 더 로직적으로 복잡한 세부 구조는 [획득 구조 레퍼런스 리서치](09-acquisition-reference-research.md)를 재료로 [획득 구조 세부 확정](10-acquisition-detail.md)에서.
- **판정**: 제출 시 "몇 개 맞음" 근접도만 공개(슬롯 비공개) + 3개 단위 자동 확정 — Golden Idol × Obra Dinn 조합, brute-force 방지.
- **세션 형태**: 연속 런 — case 3~5건, 난이도 상승, 마지막은 복합 패턴 보스 case. 한 런 30~60분.
- **실패/리스크 (독창 메커닉 — 문맥 태그 시스템)**: 라이프·HP 없음. ① run/case에 배경 상태가 있고 시작값은 생성이 정의 ② 카드 태그의 의미·정답성은 배경 상태와의 조합식으로 평가(같은 카드도 상황·캐릭터 따라 다른 답) ③ 오답 제출·카드 사용이 배경 상태를 변화시킴(상태 오염) ④ case 사이 인터루드 이벤트에서 조합식이 평가되어 일부 경로가 BAD 엔딩(run 조기 종료). 오답 코스트·실패·마스터리 천장이 이 한 시스템으로 통합. 세부 설계는 [문맥 태그 의미론 설계](12-context-tag-semantics.md)(프로토타입에 블록).
- **권태 대책**: 복합 패턴 case(조합 확장)만 루프 설계에 포함 — 규칙 변주 모디파이어·일일 사건·도감 리텐션 레이어는 제외 결정. 학습 천장 = 패턴 조합 + 문맥 태그 의미론.
- **Koster 정합**: 학습 대상이 "패턴 4종 통달"에서 "문맥에 따라 변하는 단서 의미론"으로 확장되어 마스터리 천장 확보. 게스트 단서가 새 어휘를 맥락 속에서 학습시킴("동사 먼저, 리믹스 나중"과 일치).
