## Question

caseCollection의 코어 루프는 무엇인가 — 플레이어가 반복하는 학습 가능한 시스템(Koster), 한 세션의 형태, 카드 획득 방식(플레이로 획득)과 수집물의 게임적 사용이 맞물리는 구조. [메커닉 설계 공간 서베이](01-mechanic-survey.md)의 후보 패턴과 [위키 데이터 인벤토리](02-wiki-data-inventory.md)의 실제 데이터 형태를 재료로 결정한다. 후보 루프가 좁혀지면 /prototype으로 페이퍼/코드 프로토타입을 만들어 비교한 뒤 확정.

## Resolution

2026-07-19, 그릴링 세션(MMDAL × Fable). 종이 위 확정 — 재미 검증은 [코어 루프 프로토타입](11-core-loop-prototype.md)에서, 반증 시 이 결정을 재개정한다.

- **루프 가족**: ⓑ 수집=퍼즐재료(Golden Idol형)로 MVP → 재미 검증 후 ⓐ 단서-투-덱(× StS) 확장. 서베이 권고 수용.
- **case** (핵심 명사, "case" 재정의 채택 — `CONTEXT.md` 기록): 빌드타임 생성된 사건 퍼즐 1판. case_pattern 4종이 골격, story 77의 인물·범죄유형·트롭이 소재풀. 원작 근거는 소재풀 경유로 유지, 변주 공간은 4×77로 확대.
- **수집×플레이 (C면)**: 어휘 게이트 — 추리 슬롯엔 보유 단서 카드만 사용 가능. case 생성이 플레이어 컬렉션 기반이라 "못 푸는 판" 문제 차단. + 소모형 힌트 카드(순간 전술).
- **획득 (B면)**: 게스트 단서 학습형(case 내 임시 사용 → 클리어 시 영구 획득) + 보상팩 혼용, 더 로직적으로 복잡한 세부 구조는 [획득 구조 레퍼런스 리서치](09-acquisition-reference-research.md)를 재료로 [획득 구조 세부 확정](10-acquisition-detail.md)에서.
- **판정**: 제출 시 "몇 개 맞음" 근접도만 공개(슬롯 비공개) + 3개 단위 자동 확정 — Golden Idol × Obra Dinn 조합, brute-force 방지.
- **세션 형태**: 연속 런 — case 3~5건, 난이도 상승, 마지막은 복합 패턴 보스 case. 한 런 30~60분.
- **실패/리스크 (독창 메커닉 — 문맥 태그 시스템)**: 라이프·HP 없음. ① run/case에 배경 상태가 있고 시작값은 생성이 정의 ② 카드 태그의 의미·정답성은 배경 상태와의 조합식으로 평가(같은 카드도 상황·캐릭터 따라 다른 답) ③ 오답 제출·카드 사용이 배경 상태를 변화시킴(상태 오염) ④ case 사이 인터루드 이벤트에서 조합식이 평가되어 일부 경로가 BAD 엔딩(run 조기 종료). 오답 코스트·실패·마스터리 천장이 이 한 시스템으로 통합. 세부 설계는 [문맥 태그 의미론 설계](12-context-tag-semantics.md)(프로토타입에 블록).
- **권태 대책**: 복합 패턴 case(조합 확장)만 루프 설계에 포함 — 규칙 변주 모디파이어·일일 사건·도감 리텐션 레이어는 제외 결정. 학습 천장 = 패턴 조합 + 문맥 태그 의미론.
- **Koster 정합**: 학습 대상이 "패턴 4종 통달"에서 "문맥에 따라 변하는 단서 의미론"으로 확장되어 마스터리 천장 확보. 게스트 단서가 새 어휘를 맥락 속에서 학습시킴("동사 먼저, 리믹스 나중"과 일치).

## Resolution 개정 (2026-07-20) — 통합 루프 확정

[코어 루프 프로토타입](11-core-loop-prototype.md) v1~v9 반복과 [최신 추상전략게임 메커닉 리서치](15-abstract-games-research.md)를 거쳐 정식 재개정. **위 종이 결정은 반증되지 않았다** — 루프 가족 ⓑ(Golden Idol형)·case 정의·어휘 게이트·게스트 단서 학습형·근접도+3확정·연속 런+보스·가설 선언·문맥 태그 시스템은 모두 유지·검증됨. 아래는 프로토가 **추가·구체화·재정의**한 것.

### 1. 코어 루프 재정의 — "빈칸 두루마리"에서 두 축이 함께 돈다

원래는 "추리 슬롯을 정답 카드로 채운다"였다. 리서치가 확인한 Golden Idol의 **빈칸 두루마리**(단어 카드로 사건 문장을 재구성 = 정답 판정이자 서사 조립)가 이 게임의 이미 가진 형태였고, 프로토 v6/v7이 이를 **한 보드에서 두 축이 나란히 도는 구조**로 확정했다:

- **정답 축** — 근접도("몇 개 맞음") + 3개 단위 확정 (기존)
- **서사 축** — 인접한 슬롯의 카드가 **서사 링크**를 맺어 사건 이야기를 조립, **서사 응집도**로 계측

**핵심 명제 전환**: "정답 슬롯 채우기" → **"옳으면서 앞뒤 맞는 이야기 짓기"**. 두 축은 v7에서 정렬됐다 — 정답 카드는 자기 역할에 맞으므로 **정답 배치 = 응집 full**. 서사 응집은 correctness보다 약한 신호라(오답이어도 역할만 맞으면 응집 유지) **정답을 guide**하고, 근접도가 THE 카드를 **확정**한다.

### 2. 반응 레이어 — 재미의 핵심 축 (신규, 원래 03에 없음)

플레이 반응에서 드러난 최대 결함: **"답과 오답으로만 갈리는 이진 피드백은 납작하다. 엉뚱한 카드를 넣었을 때 나오는 재미가 핵심."** 해결책으로 **드라마투르기 패턴화**를 채택:

- 오답을 "왜 틀렸나"의 **구조**로 분류·생성 — 코믹 패턴(범주 오류·행위자 오귀속·문자적 과장·규모 부조화·정반대·엉뚱한 매체 + 슈트 폴백)
- **레이든 페르소나** 부착 — 어이없는 배치엔 그의 몸짓("레이든은 관자놀이를 눌렀다. 이런 조수는 처음이었다")
- 우선순위: 감독판(손수 개그) > 정답 hit > 패턴 생성 > 폴백. 손수 저작이 커버 못 하는 조합도 구조화된 코미디로 전부 커버됨

이 축은 Koster 정합에도 기여한다 — 플레이어가 **코믹 문법**(무엇이 왜 안 맞는지)을 학습한다.

### 3. kind × frame — 게임의 의미 어휘 (신규 기반)

위 2·3축을 지탱하는 공통 어휘. **카드에 존재 범주 `kind`**(사람·사물·행위·기록·현상), **슬롯에 추리 역할 `frame`**(route·means·trace·action·motive·record·omission·scene·identity) + 역할이 받는 kind(`accepts`).

이 어휘가 (a) 코믹 반응 생성 (b) 서사 응집도 (c) 정답=코히런트 정렬을 **동시에** 만든다.
→ **[카드 스키마](04-card-schema.md)에 `kind` 필드 추가 필요**(현재 스키마 미포함). 슬롯 `frame`은 case 생성기의 출력 항목.

### 4. 문맥 태그 = 영역 다수결 (Tigris 오마쥬)로 구체화

원래 "배경 상태 × 태그 조합식"이라는 추상 서술을, **두 극의 줄다리기 트랙**으로 구체화:

- 주목 = **은밀 ◁▷ 공개**, 신뢰 = **강압 ◁▷ 신중**. 확정 카드의 태그가 트랙에 영향력을 놓는다
- **다수결 임계를 넘으면 판정 규칙이 flip** — 같은 슬롯, 다른 답(조건부 정답)
- 임계 초과 상태로 인터루드를 맞으면 BAD 엔딩(기존 유지)

→ [문맥 태그 의미론 설계](12-context-tag-semantics.md)의 기계적 뼈대. 영향력 **타이밍**(현재는 확정 카드만 영향)은 12에서 확정.

### 5. 인터루드 = 조사 미니루프 + AP 배분 퍼즐 (템포·행동 경제)

원래 "인터루드 이벤트"(선택 메뉴)에서 확장:

- **다음 사건 예고** + **조사 리드**(짚으면 다음 case 힌트·배경 발견)
- **행동력(AP) 배분** — 조사 리드 각 1AP + 행동(트랙 조작·힌트 확보) 1~3AP. **전부는 못 한다 = 기회비용**
- 서사 선택지는 무료(이야기 비트라 자원 게이트 안 함)

### 6. 재확인(검토) 루프 — 제약 만족의 인간 검증 스텝

조립한 이론을 대조해 **성립/미흡/반증** 판정 + **약한 고리 지목**. 조립 → 검토 → 수정 → 재검토의 탐정 루프. (Obra Dinn 3확정 + logic-grid CSP의 "단계적 설명" 계보.)

### 7. 클리어 피드백 단계

사건을 푼 마지막 제출의 반응·영향력을 보여준 뒤 "계속"으로 진행. (즉시 보상 화면으로 튀면 가장 좋은 피드백이 사라진다 — 프로토에서 발견·수정.)

### 새 제약 — case 생성기의 **이중 제약**

통합의 귀결로 case 콘텐츠는 두 조건을 **동시에** 만족해야 한다:

1. **풀 수 있음** — 어휘 게이트 솔버빌리티(보유+게스트만으로 해결 가능, 소프트락 없음)
2. **정답이 이야기로 성립함** — 정답 배치가 코히런트 서사 사슬을 이룸(정답 슬롯 순서 = 서사 인과 순서)

이는 case 생성 파이프라인 설계의 필수 입력이다(지도 "Not yet specified"의 case 생성기 항목).
