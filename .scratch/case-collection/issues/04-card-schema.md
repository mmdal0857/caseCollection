# 카드 스키마와 카드화 대상

Status: closed
Labels: wayfinder:grilling
Assignee: MMDAL (fable session, 2026-07-19)
Blocked-by: 03

## Question

어떤 위키 노드 타입이 카드가 되는가(사건 패턴·단서 유형·인물·작품·수법 등), 카드 한 장의 스키마는 무엇인가(필드, 희귀도, 아트 슬롯, 텍스트 분량), 컬렉션은 어떻게 구조화되는가(세트/시리즈/작가별). 코어 루프가 요구하는 카드의 게임적 속성이 입력. "case" 용어 재정의가 필요하면 /domain-modeling으로 확정하고 `CONTEXT.md`에 기록.

## Resolution

2026-07-19, 그릴링 세션(MMDAL × Fable). 용어는 `CONTEXT.md`에 반영(패턴 카드·가설 선언·수사 노트·검증).

- **카드화 대상**: 영구 컬렉션 = **단서 카드 49**(clue_type) + **패턴 카드 4**(case_pattern). story·work·source_page는 카드가 아니라 case 생성 소재로만 사용.
- **패턴 카드의 게임적 사용처 = 가설 선언 어휘**: 추리 제출에 "이 case의 골격은 X" 선언 슬롯을 추가하고, 보유·게스트 패턴 카드만 선언 가능(어휘 게이트의 패턴판), 적중 시 정보 보상(예: 근접도 상세화). [코어 루프 확정](03-core-loop.md)의 소폭 개정 — [코어 루프 프로토타입](11-core-loop-prototype.md)에서 검증, 반증 시 재개정.
- **힌트 카드**: 소모형·순수 수제(위키 비원천, 익명적 도구 컨셉 — 탐정 플레이버 안 기각). 효과 세부는 프로토타입·스펙 단계에서.
- **단서 카드 스키마**: `id`(위키 clue id 링크) / `name` / `suit`(physical·behavioral·documentary·forensic) / `tags[]`(앞면 공개) / `insight`(발견 상태: 미확인→검증됨) / `text`(의미 텍스트, 검증 후 공개) / `art`(개별 슬롯). **수치 속성·희귀도 없음** — 층위는 카드 종류·슈트만, 희소성 연출은 [획득 구조 세부 확정](10-acquisition-detail.md) 소관.
- **비공개 의미형 + 수사 노트**: 위키 inference를 앞면에 싣지 않는다. 카드가 정답 확정(3개 단위)에 포함될 때마다 수사 노트가 해금돼 의미 텍스트가 열린다 — 카드가 성장하는 객체. 패턴 카드도 동일 insight 구조(가설 적중으로 검증).
- **텍스트**: 전량 카드용 재작성(위키 원문 직수입 아님). 재작성본은 게임 로컬 데이터, 위키 원천 id 링크로 동기화 지점 유지. 재작성 작업(49+4+힌트)은 스펙에 포함될 실행 작업 — wayfinder 티켓 아님.
- **문맥 태그 값의 출처 — 2단계 승격**: MVP·프로토타입은 게임 로컬 수제 시드 → [문맥 태그 의미론 설계](12-context-tag-semantics.md) 확정 후 원문 기반 빌드타임 추출로 승격([원문 기반 태그 추출 승격 스펙](14-tag-extraction-promotion.md)). 팩트 확인: catalog 110권 전부 `pg_id` 보유, 원문은 Drive `pd_novels/` 수집 + 로컬 `f:/Project/out/raw_texts/`(현재 5권). "책 추가 → 자동 확장" 야망이 공식 경로로 승격. 이 결정은 [OUT 코어 경계](06-core-boundary.md)의 직접 입력.
- **아트**: 카드별 개별 슬롯 + 비어 있으면 슈트 공용 프레임 폴백, 단계 채움. 파이프라인은 [카드 아트 파이프라인](13-card-art-pipeline.md)으로 안개 졸업.
- **컬렉션 구조**: 세트/시리즈 없음. 슈트 4종+패턴 단일 뷰, 진행도는 **보유율 × 검증율 2축**. 작가 캐넌 세트는 채택 안 함(source_page 15/27 미배선).

## Comments

- 2026-07-20 [코어 루프 재개정](03-core-loop.md)의 파급 — **스키마에 `kind` 필드 추가 필요**. 단서 카드의 **존재 범주**(사람·사물·행위·기록·현상)로, 프로토(v3~v9)에서 이 어휘가 ①오답 코믹 반응 생성(kind × 슬롯 frame 부조화) ②서사 응집도 ③"정답=코히런트" 정렬을 **동시에** 지탱하는 토대임이 확인됨. 즉 `kind`는 플레이버가 아니라 **판정·반응·서사의 기계적 입력**. 개정 스키마: `id / name / suit / kind / tags[] / insight / text / art`. (슬롯의 `frame`·`accepts`는 카드가 아니라 case 생성기의 출력 항목.) 값 부여는 49장 재작성 작업에 포함 — 위 "텍스트 전량 카드용 재작성"과 같은 단계.
