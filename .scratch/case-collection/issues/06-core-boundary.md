# OUT 코어 경계

Status: closed
Labels: wayfinder:grilling
Assignee: MMDAL (opus session, 2026-07-19)
Blocked-by: 04

## Question

OUT에서 추출하는 코어의 경계는 어디인가. 시작 가설은 최소(생성된 위키 데이터 + `pd_wiki` 조회 레이어). [카드 스키마와 카드화 대상](04-card-schema.md)이 확정한 게임의 실제 데이터 요구를 기준으로, wiki-agent 생성 파이프라인·pg_downloader/pg_pd_filter·graphify 포함 여부를 결정한다. "책 추가 → 카드 풀 확장" 야망이 경계 안으로 들어오는지 여기서 판정.

## Resolution

2026-07-19, 그릴링 세션(MMDAL × Opus). 시작 가설(최소: 데이터+조회)을 넘어 **콘텐츠 파이프라인(C)**으로 확정 — "더 다양한 이야기/커스텀" 요구가 생성기를 경계 안으로 끌어들였다.

**코어의 형태**: 추출 코어 = **재실행 가능한 빌드타임 콘텐츠 파이프라인**. 산출물 = **공유 가능한 데이터 팩**. 게임은 정적으로 팩을 로드한다(런타임 LLM·서버 0 유지 — 정적 클라이언트 제약 불변). 코드는 **OUT-구체(X)**로 추출하고, 일반화는 코드가 아니라 **플로우 스킬(절차)**에 담는다(n=1 범용 추상화 함정 회피, wayfinder "모듈+플로우" 노선 준수).

**모듈 경계**:
- **IN (추출 코어)**:
  - `pg_downloader.py` · `pg_pd_filter.py` — 구텐베르크 획득 + PD 필터. X라 특화 코드 OK, "책 추가" 직결.
  - `text_cleaner.py` + `cleaned_texts/` — 생성 전처리.
  - `wiki-agent/` + `wiki_seeder.py` — 생성기(C의 핵심). **통째로 추출**하고, 게임은 하류에서 필요한 노드 타입만 선택(Raiden·episode 출력은 무시하되 **수술하지 않음** — 조기 최적화 회피).
  - `docs/wiki/` — 현재 동결 출력 = **씨앗 데이터셋**(시작 데이터로 동행).
  - `pd_wiki/` — α 조회·컨텍스트 조립·익스포트 단(익스포트/팩 포맷 세부는 07).
- **OUT (OUT 잔류)**:
  - `episode_generator.py` — Ren'Py VN 전용. 단 게임의 build-time **case 생성기의 참고 원형**(안개 "case 생성 파이프라인").
  - `game/` — Ren'Py(다른 제품).
  - `graphify-out/` — 코드 구조 그래프, 위키 무관([위키 데이터 인벤토리](02-wiki-data-inventory.md) 확인).

**게임 무관 원칙(L)**: 코어는 caseCollection을 몰라야 재사용된다. 게임 고유 **문맥 태그 추출은 코어에 넣지 않고**, 코어 산출물(`cleaned_texts/` + 위키 데이터)을 소비하는 **게임측 레이어**로 둔다 — [원문 기반 태그 추출 승격 스펙](14-tag-extraction-promotion.md)의 "파이프라인이 어디 사는가" 질문에 대한 답(게임측·스펙 ①). 14는 12(태그 의미론) 확정 후 추출 *세부*를 계속 스펙한다.

**"책 추가 → 확장" 야망**: 경계 안으로 채택하되 **빌드타임 저작 경로**로 한정. 모딩은 **데이터 팩 모딩(a)**만 — 모더가 파이프라인을 오프라인 실행해 팩을 만들고 배포, 정적 게임은 팩을 **로드만**. 플레이어 런타임 추출(클라이언트 LLM (b) / BYO 키 (c))은 정적 클라이언트·런타임 LLM 배제 제약을 깨므로 **배제**(원하면 차팅 재개 사안).

**주의 — "카드 풀 확장"의 정확한 의미**: 카드 로스터(단서 49 + 패턴 4)는 **고정 분류 체계**라 책 추가로 늘지 않는다. 책 추가로 커지는 것은 **case 소재 풀(story)과 문맥 태그의 풍부도**이지 카드 종류가 아니다. 카드 종류를 늘리려면 분류 체계를 재큐레이션해야 하며 그건 별도 결정.

**낳은 것**:
- **07(모듈 패키징)** 프론티어 진입 — 이 IN/OUT이 직접 입력, 익스포트/데이터 팩 물리 포맷은 07 소관.
- **신규 16([외부 데이터 팩 로드](16-external-data-pack-loading.md))** — 모딩 소비측(게임이 팩을 로드·검증·병합), blocked-by 07, 스펙 ①. *(15는 동시 세션의 추상전략게임 리서치 티켓과 충돌해 16으로 채번.)*
- **14** — 게임측 레이어로 위치 확정(코멘트 기록).
