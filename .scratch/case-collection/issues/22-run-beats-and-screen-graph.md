## Resolution

- 화면 그래프를 `Home → Briefing → Case Compose → Case Review → Clear Feedback → Interlude → 다음 Briefing/Boss → Ending → Run Summary → Home`으로 구현했다.
- 검토는 제출과 분리했다. 검토 중에는 패턴·슬롯·힌트가 잠기며, `수정하기`로 compose에 돌아가거나 `최종 제출`로만 판정을 확정할 수 있다.
- 클리어 직후 별도 피드백 화면에서 마지막 제출 반응과 영구화된 게스트 카드를 보여준다. 보상팩·shop 상태, 액션, 화면은 제거했다.
- 인터루드는 AP 2, `정찰/면담/안정` 세 행동 중 정확히 두 개만 선택하고 이월하지 않는다. 정찰은 공개 정보만, 면담은 다음 사건 allowlist의 측면 하나만, 안정은 실패축 한 단계만 다룬다.
- 내부 측면 키는 신규·기존 snapshot 모두 표시 직전에 카드명과 측면명으로 바꾼다.
- `RunSnapshot@1`은 strict envelope(`format/version/savedAt/actionSeq/game`)로 원자 저장하며 손상·미래 버전 원문을 보존하고 복구를 거부한다. 재개 뒤 같은 비가역 액션은 seq와 상태를 중복 변경하지 않는다.
- BAD 임계 한 단계 전 경고를 상태에 기록하고, 경고 없이 BAD 이벤트로 진입하지 못하게 했다.

검증: `npm run smoke:run-flow`, `npm run smoke:run-session`, 기존 `npm run smoke`, `npx tsc --noEmit`, `npm run build` 통과. 실제 브라우저에서 compose/review 잠금/수정/최종 제출/clear/interlude AP2/세 번째 행동 비활성/다음 briefing까지 완주했다.

## Question

case **사이**의 시간을 설계한다 — 브리핑 → case → (재확인 → 클리어 피드백) → 인터루드 → … → 보스 → 엔딩의 리듬, 그리고 그 화면들이 이루는 그래프(무엇에서 무엇으로 가는가, 나갔다 돌아올 수 있는가, 저장·재개는 어디에 붙는가).

[03 재개정](03-core-loop.md)이 신설한 **⑥재확인(검토) 루프**와 **⑦클리어 피드백 단계**는 결정만 있고 화면이 없다. 인터루드도 "조사 미니루프 + AP 배분 퍼즐"까지만 정해져 있다.

## 이미 정해진 것 (입력)

- **[03](03-core-loop.md)**: 연속 런 3~5건 + 복합 패턴 보스. 인터루드 = **조사 미니루프**(다음 사건 배경·힌트 발견) + **AP 배분 퍼즐**(전부는 못 한다). ⑥재확인 루프 = 조립한 이론 대조해 성립/미흡/반증 + **약한 고리 지목**. ⑦클리어 피드백 = 마지막 제출의 반응·영향력을 보여준 뒤 진행.
- **[12 §7](12-context-tag-semantics.md)**: 실패는 **등급형**. 죽는 방향 둘(공개 과다 = 언론 재판 · 강압 과다 = 수사반 붕괴). **반드시 예고된다.** 4~5런에 1회 수준. 은밀·신중 극단은 실패가 아니라 측면 막힘.
- **[08 §③](08-mvp-scope.md)**: run 완주 + 인터루드 AP + 보스 + 엔딩 **MVP 안**.
- **[05](05-web-stack.md)**: 정적 클라이언트, localStorage 저장.

## 뾰족한 지점

1. **인터루드에 무엇이 남았는가 — 스코프 충돌 확인 필요.** [08 §③](08-mvp-scope.md)은 인터루드 AP를 MVP에 넣으면서 [10](10-acquisition-detail.md)의 획득 경제(수사 포인트 화폐·인터루드 진열 구매·완주팩)를 **전량 기각**했다. 그런데 03의 인터루드는 "AP 배분 퍼즐"이고 10의 진열 구매가 그 배분처의 큰 축이었다. **살 것이 없는 인터루드에서 AP를 무엇에 쓰는가** — 이 티켓이 답하거나, 답할 수 없으면 08로 되돌려야 한다.
2. **실패 예고를 어디에 싣는가.** 12 §7의 "반드시 예고"가 지켜지려면 예고가 눈에 띄어야 하는데, [20](20-play-screen-hierarchy.md) 관찰 3번은 현재 미터가 화면에서 가장 안 보인다고 기록했다. 예고는 상시 미터인가, 인터루드의 전용 비트인가, 둘 다인가.
3. **재확인 루프가 별도 화면인가 제출의 일부인가.** 03은 "성립/미흡/반증 + 약한 고리 지목"까지 정했으나, 이게 제출 버튼의 결과 표시인지 독립된 검토 단계인지는 미정. 독립 단계면 run의 템포가 바뀐다.
4. **저장·재개의 단위.** run 중간에 껐다 켜면 이어지는가, run 단위로만 저장되는가. BAD 엔딩이 등급형이라 "망한 run을 되돌리고 싶은" 압력이 생긴다 — 세이브 스커밍을 허용할 것인가가 설계 결정이다.
5. **첫 진입.** 08 §①의 완료 조건은 "올려둔 빌드"이고 판정은 마켓플레이스 관심 신호다. 처음 열었을 때 무엇을 보는가는 그 신호에 직결된다.
