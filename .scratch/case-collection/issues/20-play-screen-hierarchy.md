## Question

[08 §②](08-mvp-scope.md)가 "Svelte UI(~1,100줄)는 폐기하고 새로 짓는다"로 정했고, [17](17-context-semantics-prototype.md) 총평이 재미의 남은 축으로 **"시각화"**를 지목했다. [13](13-card-art-pipeline.md)이 스타일 키를 확정하면서 08 §⑦의 순서 조건("스타일 키 우선, 그 후 UI")이 충족됐다 — 이제 화면을 설계할 수 있다.

정할 것: **플레이 화면의 정보 위계** — 무엇이 화면의 주인공이고, 배경 상태·얼굴 선택·반응 레이어·49장 컬렉션이 각각 어디에 어떤 크기로 사는가. 산출: 화면 설계안(변형 비교로 결정) + 스펙 ①에 편입할 레이아웃 규약.

**이 티켓은 "예쁘게"가 아니라 "무엇이 커야 하는가"를 정한다.** 룩앤필은 13이 스타일 키로 이미 고정했다.

## 현행 관찰 (v10 실물, 2026-07-25 — 13 세션에서 채집)

프로토 v10 플레이 화면(`온실의 밀실`)을 실제로 띄워 채집한 문제들. 재설계의 입력이지 해결책이 아니다.

1. **두루마리가 화면의 주인공이 아니다.** [15](15-abstract-games-research.md)가 "통합 척추"로 지목한 빈칸 추리문이 여러 패널 중 하나로 끼여 있고, 세로 공간은 **카드 그리드(11장)가 더 많이** 먹는다. 퍼즐이 카드 목록보다 작다.

2. **배경이 없다.** 화면 전체가 평평한 `#14120f`. [13 §⑦](13-card-art-pipeline.md)이 배경 = **신뢰축 장면 × 주목축 그레이딩**으로 정했으나 미구현이고, 이게 17 총평의 "시각화"가 가리키던 가장 큰 지렛대일 가능성이 높다.

3. **미터가 헤더에 눌려 있다.** 주목·신뢰·봉인 3축이 상단바에 밀려 레이블이 세로로 접힌다. [12 §7](12-context-tag-semantics.md)은 실패 방향이 **반드시 예고**되어야 한다고 정했는데, 예고를 나르는 위젯이 화면에서 가장 눈에 안 띈다.

4. **프로토 디버그 잔재가 플레이 화면 한복판에 있다.** "잠금 시점 (ticket 17 Q1 — 바꿔가며 느껴볼 것)" 3버튼이 두루마리 **위**를 차지한다. 17에서 즉시 잠금으로 확정됐으므로 이 위젯은 죽었다 — 08 §②의 "10번 덧칠된 층"의 표본.

5. **49장으로 못 늘어난다.** 손패·컬렉션이 평평한 그리드라 20장에서 이미 스크롤을 먹는다. [04](04-card-schema.md)는 컬렉션을 슈트 4종 + 보유율×검증율 2축으로 정했지만 **플레이 중 손패**의 추림 수단은 정해진 적이 없다. 얼굴이 잠기면 쓸 수 있는 카드가 줄어드는데(어휘 게이트 × 배경 상태), 그 가용성이 손패에 보이지 않는다.

6. **반응 레이어에 자리가 없다.** [11](11-core-loop-prototype.md)이 "재미의 핵심 축"으로 지목하고 13이 인물 아트까지 승인한 드라마투르기 반응(레이든)이 화면에 고정 좌석을 갖고 있지 않다.

7. **얼굴 선택이 화면에 드러나지 않는다.** [12](12-context-tag-semantics.md)의 "배치 = 수(手)" — 놓는 순간 얼굴이 확정·잠기고 앞으로 전파되는 것 — 이 코어 메커닉인데, 선택 순간과 전파 결과가 어디서 보이는지가 레이아웃에 자리 잡혀 있지 않다.

## 참고 — 13이 남긴 미구현 결정

- 배경 = 신뢰축 장면 3장 × 주목축 CSS 그레이딩 (연속 전이)
- 카드 아트 = 사물 1장 × 태그 처리 5종 CSS — **얼굴이 잠길 때 전이로 바뀐다**. 7번 항목의 유력한 답이 여기 있다
- 카드 프레임 = 전면(148×206), 아트 슬롯 + 슈트 폴백은 `CardChip.svelte`에 이미 승격됨
- 프로토 하네스 `protoart.svelte.ts` · `ArtSwitcher.svelte`는 **THROWAWAY** — 재작성 시 삭제

## Resolution

### 진단 — 개별 수정으로는 안 풀린다

v10의 병은 관찰된 7개 문제의 합이 아니라 **화면이 패널 모음**이라는 한 가지다. 두루마리·카드 그리드·미터·디버그가 **형제 패널로 면적을 다툰다.** 그래서 "두루마리를 크게"가 아니라 **층을 나눈다** — 상태를 나르는 층(배경), 주인공 층(두루마리), 대기 층(손패)이 서로 면적을 다투지 않게 한다.

### 위계 (z-order 및 면적 예산)

| 층 | 역할 | 면적 예산 (데스크톱 16:9) |
|---|---|---|
| 0 배경 | **상태의 몸** — 신뢰축 장면 3장 × 주목축 CSS 그레이딩, 연속 전이 | 전면 (viewport 전체) |
| 1 계기 스트립 | 3축 정밀 판독. 상시 얇게, **임계 접근 시에만 승격** | 상단 ≤48px (승격 시 ≤96px) |
| 2 **두루마리** | **주인공.** 빈칸 추리문 | 중앙, 세로 **≥45%** |
| 3 반응 띠 | 레이든 드라마투르기 **고정 좌석** | 두루마리 하단 접합, **높이 예약 고정** |
| 4 손패 | 슈트 4스택. 접힘이 기본, 펼침은 임시 | 하단 레일 ≤180px |

### 용어 (플레이 화면 — 이 표가 정본)

새 이름을 즉석에서 만들지 말 것. 2026-07-26에 실제로 사고가 났다 — `.stack-fan`을 가리키려고 **"부챌침"이라는 없는 단어를 만들어** 티켓·커밋 17곳에 퍼뜨렸다. 정본은 이미 이 티켓에 있던 **"펼침"**이었다.

| 한국어 (정본) | 쉬운 풀이 | 코드 |
|---|---|---|
| **배경** | 상태를 나르는 방 그림 | `.stage-background` / `StageBackground.svelte` |
| **계기 스트립** | 주목·신뢰·봉인 3축 숫자 띠 | `.instrument-strip` / `Meters.svelte` |
| **두루마리** | 빈칸을 채우는 추리문 ([15](15-abstract-games-research.md)의 "빈칸 두루마리") | `.scroll-layer` |
| **빈칸 / 슬롯** | 카드를 놓는 자리 | `.slot` |

| **펼침** | 스택을 눌러 카드가 부채꼴로 나오는 것 | `.stack-fan` / `.fan-card` |

### 세 가지 결정 원리

**① 배경이 미터다.** [13 §⑦](13-card-art-pipeline.md)이 이미 배경 = 신뢰 장면 × 주목 그레이딩으로 정했으므로, 방 자체가 상태를 나른다. **문제 2와 문제 3이 한 수로 함께 풀린다** — 미터가 헤더 위젯일 필요가 없어지고, [12 §7](12-context-tag-semantics.md)이 요구한 "실패 방향 예고"가 방이 조여드는 것으로 나타난다. 정밀 판독용 스트립은 남기되 **임계에 접근할 때만 커진다**: 예고를 나르는 위젯이 예고할 때 실제로 커져야 한다(v10은 그 반대였다 — 가장 중요한 정보가 가장 안 보였다).

**② 손패는 슈트 4묶음으로 접힌다.** 평평한 그리드는 49장에서 죽는다(문제 5). 슈트별 스택 4개만 화면에 두고 펼칠 때만 부챌치면 **장수가 늘어도 슬롯은 항상 4개**다. 부수 이득 셋: 슈트가 곧 추림 어휘가 되어 [21](21-collection-and-notes-screen.md)과 어휘를 공유하고(따로 정하면 플레이어가 두 번 배운다 — 21 §3의 요구), 스택 뱃지 `가용/보유`가 문제 5의 "가용성이 안 보인다"를 해소하며, 어휘 게이트 × 배경 상태로 쓸 수 있는 카드가 줄어드는 것이 **숫자로 보인다**.

**③ 전파는 새 위젯 없이 카드가 표시한다.** 문제 7의 답은 13이 이미 줬다 — 카드 아트 = 사물 1장 × 태그 처리 5종 CSS이고 **얼굴이 잠길 때 처리가 전이한다.** 그러므로 배치 순간 (i) 놓인 카드의 처리가 전이하고 (ii) 전파되는 이웃 슬롯이 **순차 전이**한다. [12](12-context-tag-semantics.md)의 "배치 = 수(手)"가 애니메이션 경로로 보인다. 전용 위젯을 만들면 오히려 메커닉이 카드에서 분리된다.

### 관찰 7건 대응

| # | 관찰 | 해소 |
|---|---|---|
| 1 | 두루마리가 주인공이 아니다 | 세로 ≥45% 예산 + 카드 그리드를 하단 레일로 강등 (층 분리) |
| 2 | 배경이 없다 | 층 0 신설 — 13의 미구현 결정 구현 |
| 3 | 미터가 헤더에 눌림 | 배경이 아날로그 미터, 스트립은 임계 시 승격 |
| 4 | 디버그 잔재 | **삭제** (17에서 즉시 잠금 확정 — 위젯이 죽었다) |
| 5 | 49장으로 못 늘어남 | 슈트 4스택 + 가용/보유 뱃지 |
| 6 | 반응 레이어에 자리 없음 | 층 3 고정 좌석, **높이 예약**(반응 없을 때도 자리 유지 — 없으면 레이아웃이 튄다) |
| 7 | 얼굴 선택·전파가 안 보임 | 카드 아트 처리 전이 + 이웃 순차 전이 |

### 레이아웃 규약 (스펙 ① 편입분)

1. **면적 예산은 규약이다.** 두루마리 세로 ≥45%를 어기는 변경은 위계 위반으로 본다.
2. **배경은 장식이 아니라 상태 표시**다. 배경을 정적 이미지로 대체하면 미터 승격 규칙과 함께 깨진다.
3. **반응 띠는 높이를 예약**한다. 내용 유무로 레이아웃이 흔들리면 배치의 타격감이 죽는다.
4. **손패 슬롯은 항상 4개**(슈트 수). 카드 총량이 늘어도 슬롯 수는 불변.
5. **추림 어휘는 슈트 4종 + 가용성 2상태**로 고정하고 [21](21-collection-and-notes-screen.md)과 공유한다.
6. **전파 표시에 전용 위젯을 만들지 않는다** — 카드 아트 처리 전이가 유일한 채널.
7. **모바일**: 적층 순서를 유지하고 두루마리 우선. 계기 스트립은 승격 시에만 표시, 손패 레일은 높이 축소.
8. **z-order** — 원래 문언(`배경(0) < 계기(1) < 두루마리(2) < 반응(3) < 손패 펼침(4)`)은 **2026-07-26 [24](24-play-screen-build.md) 플레이 판정에서 스펙 버그로 판명돼 개정**했다. 그 순서의 의도는 "**배경이 콘텐츠 아래**"였는데, 문언대로 구현하니 계기 스트립이 두루마리보다 낮아 스크롤 콘텐츠에 덮였다 — 규약이 해소하려던 관찰 3번(미터가 눌려 있다)이 형태만 바뀌어 되살아났다.
   - **개정된 규약**: 배경은 항상 최하층(0). **판독·계기는 콘텐츠보다 위**여야 한다 — 상태 표시가 콘텐츠에 가려지면 그 위젯은 존재하지 않는 것과 같다. 손패 펼침만 유일한 오버레이로 최상층.
   - **파생 규약 하나 추가**: **플레이 층 컨테이너는 뷰포트를 넘지 않는다.** 넘치는 순간 페이지가 스크롤되고, 그때 sticky 요소가 자기 그리드 행에서 떨어져 이웃을 덮는다. 컨테이너가 뷰포트에 맞으면 계기는 sticky 없이도 1행에 항상 보이므로 **sticky를 쓰지 않는 것이 정답**이었다(24에서 sticky 제거로 해소).
   - **단일 진리원 규칙**: 상단바 높이 같은 값을 두 곳 이상에서 각각 가정하지 않는다. 실제로 하나의 상단바(40px)를 컨테이너 높이는 54px, sticky 오프셋은 48px로 가정해 겹침이 발생했다 — `--topbar-h` 변수로 묶었다.

### 미결 (여기서 정하지 않음)

- 손패 펼침 인터랙션의 정확한 형태(펼침 각도·클릭 vs 호버)와 계기 승격 임계값 → **구현 프로토에서 튜닝**.
- 크롬 언어(테두리·모서리·타이포 스케일) → [23 인터페이스 비주얼 시스템](23-interface-visual-system.md) 소관. 이 티켓은 "무엇이 커야 하는가"만 정했다.
- run 단위 화면 전이(재확인 루프·클리어 피드백) → [22 run 골격 비트와 화면 그래프](22-run-beats-and-screen-graph.md) 소관.

**/ 기각**: B(두루마리 전면 + 손패 오버레이) — 두루마리 면적은 최대지만 배치가 "보드 위의 수"보다 "목록에서 골라 닫기"로 느껴져 12의 코어 메커닉 감각과 배치된다. C(좌우 분할) — 가로 공간을 살리지만 **배경 장면의 면적이 줄어 원리 ①의 지렛대가 약해진다**(17 총평이 "시각화"를 남은 재미 축으로 지목한 것과 역행), 모바일 전면 재배치 필요.
