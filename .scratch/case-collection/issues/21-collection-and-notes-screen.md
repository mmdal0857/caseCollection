# 컬렉션과 수사 노트 화면

Status: open
Labels: wayfinder:prototype
Assignee:
Blocked-by: 20

## Question

수집물이 **보상으로 느껴지는 표면**을 설계한다. [04](04-card-schema.md)가 "진행도 3축 표시는 **컬렉션 UI 사안** — 스펙에서 다룸"으로 명시적으로 미뤄둔 항목을 여기서 받는다.

정할 것: 49장 + 패턴 4장을 어떻게 훑는가 · 진행도 3축(보유 / 아는 얼굴 수 / 전체 얼굴 수)을 한 화면에서 어떻게 읽히게 하는가 · **수사 노트**(얼굴별 해금 기록 + 줄 그어진 오답 해석)가 카드와 어떤 관계로 놓이는가.

## 이미 정해진 것 (입력)

- **[04](04-card-schema.md)**: 세트/시리즈 없음. 슈트 4종 + 패턴 단일 뷰. 진행도 = 보유율 × 검증율 2축 → **17 검증 후 3축으로 깊어짐**(보유 / 아는 얼굴 / 전체 얼굴). 카드별 아트 슬롯 + 슈트 폴백, 단계 채움.
- **[12 §4](12-context-tag-semantics.md)**: **수사 노트가 어휘 게이트를 심화한다** — 해금된 얼굴만 실제로 쓸 수 있다(보유 ≠ 앎). 게스트는 카드뿐 아니라 **얼굴도 빌려준다**. **오답 해석도 줄 그어진 채 기록된다** — 즉 드라마투르기 반응 자체가 수집물이다.
- **[08 §③](08-mvp-scope.md)**: 컬렉션 화면(보유×검증 축)과 게스트 영구 획득은 **MVP 안**.
- **[13](13-card-art-pipeline.md)**: 카드 = 전면 프레임(148×206), 아트 = 사물 1장 × 태그 처리 5종 CSS. **얼굴이 잠기면 처리가 전이로 바뀐다.**

## 뾰족한 지점

1. **"보유했지만 모르는 카드"를 어떻게 그리는가.** 12의 핵심 재미가 다면성 발견인데, 컬렉션이 "가졌다/못 가졌다"만 보여주면 그 축이 화면에서 사라진다. 미해금 얼굴은 자리를 비워 보여줄 것인가(몇 개인지 알려줌), 아예 감출 것인가(개수도 모름).
2. **줄 그어진 오답이 자산인가 부채인가.** 12는 오답 기록을 수집물로 봤다. 그렇다면 노트는 "틀린 목록"이 아니라 읽는 재미가 있어야 한다 — 레이든 반응이 여기 쌓이는가.
3. **49장 브라우징.** 슈트 4종 필터만으로 충분한가, 얼굴 해금 상태·검증 여부로도 추려야 하는가. [20](20-play-screen-hierarchy.md)의 핸드 추림과 같은 어휘를 써야 한다(따로 놀면 두 번 배운다).
4. **플레이 중 조회와 메타 조회가 같은 화면인가.** case 도중 "이 카드 얼굴이 뭐였지"를 보는 것과, run 밖에서 컬렉션을 감상하는 것은 다른 목적이다.

## Comments

- 2026-07-26 **§3(49장 브라우징)의 어휘가 [20](20-play-screen-hierarchy.md)에서 확정됐다.** 20이 플레이 중 핸드를 **슈트 4스택 + 가용/보유 뱃지**로 정하면서, 이 티켓이 요구한 "20의 핸드 추림과 같은 어휘"가 먼저 정해진 상태로 넘어온다.
  - **고정된 추림 어휘**: 슈트 4종 × 가용성 2상태. 컬렉션도 이 두 축을 1급으로 쓴다 — 여기서 다른 축(예: 검증 여부로 먼저 접기)을 1급으로 올리면 플레이어가 두 번 배운다(20 규약 5).
  - **§1(보유했지만 모르는 카드)에 입력 하나**: 플레이 화면은 **가용/보유를 숫자로 병기**한다(`3/12`). 즉 플레이 중에는 "몇 장을 못 쓰는지"가 이미 노출된다. 컬렉션에서 미해금 얼굴 개수를 감추면 두 화면의 정보량이 어긋나므로, **자리를 비워 보여주는 쪽**이 20과 정합적이다. 최종 판단은 이 티켓 소관.
  - 진행도 3축(보유 / 아는 얼굴 / 전체 얼굴)은 여전히 이 티켓이 정한다 — 20은 플레이 화면의 2축 뱃지만 정했다.
