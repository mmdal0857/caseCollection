## Question

[카드 스키마와 카드화 대상](04-card-schema.md)에서 카드별 개별 아트 슬롯 + 슈트 공용 프레임 폴백 + 단계 채움이 확정됐다. 아트의 실물을 정한다: 스타일 방향(시안 생성·비교로 결정), 카드 프레임 + 슈트 공용 폴백 아트 4종 디자인, 개별 아트 53장(단서 49 + 패턴 4)과 힌트 카드의 제작 파이프라인 — 기존 로컬 무과금 체계(ComfyUI·nano-banana) 재사용 여부와 절차 — 그리고 MVP에서 채울 범위. 시안 비교는 큐레이션 뷰(sprite-gen) 활용 가능. 산출: 스타일 가이드 + 파이프라인 절차(스펙 ①에 편입).

## Resolution

**스타일 A(플랫 셀 누아르) + 전면 프레임 + 태그 결합.** 아트 = **사물(명사) × 태그 처리(형용사)**이고, **명사는 생성하고 형용사는 계산한다.**

### 확정

**① 스타일 = A, 플랫 셀 누아르** (사용자 판단). 하드 잉크 컨투어·평면 검정 덩어리·그라데이션 없음·절제된 팔레트. 시대 흐리기(양식화) 방향이며 Dead Letters 레이든 스프라이트와 같은 시각 언어라 인물 자산이 그대로 붙는다. **/ 기각**: B 에칭 도감(큰 이미지에선 최고였으나 **92px에서 크로스해칭이 노이즈로 뭉개지고**, 크림 종이가 `#14120f` 그리드에서 혼자 타올라 아트 있는 카드만 "진짜"로 보인다), C 증거 사진(추상 카드가 장면이 되고 53장 일관성 최난이도), D 실루엣(가독성·일관성은 최고지만 **평평한 사각 사물을 구분 못 한다** — 장부와 기차표가 둘 다 그냥 사각형, 실측 6장 중 2장 실패).

**② 프레임 = 전면**(카드 148×206, 아트가 카드 전체, 텍스트는 하단 스크림 위). **/ 기각**: 밴드(상단 띠), 액자(표본 플레이트 + 여백).

**③ 카드 아트 = 사물 × 태그 처리.** 사용자 방향 "포함하고 있는 태그의 이미지들이 결합되어야". 태그는 게임의 역학 축(주목 은밀↔공개 / 신뢰 강압↔신중 / 논리)이므로, **아트가 이 카드가 미터를 어느 쪽으로 미는지 말한다.**

**④ 형용사는 굽지 않고 계산한다 (에이전트 권고 — 사용자 재검토 가능).** 측면마다 이미지를 구우면 ≈150장, 계산하면 **49장 + 처리 5종**. 근거는 `content.ts` 실측: 카드 20종에 측면 55개인데 **태그 조합은 7종뿐**이고 상위 5종(논리 18·은밀 13·공개 10·신중 7·강압 5)이 55개 중 **53개**를 덮는다. 2태그 조합은 각 1건(55개 중 2개)뿐이라 처리 2개를 겹쳐 처리한다. 부수 이득이 본 이득보다 클 수 있다 — 계산본은 **측면이 확정되는 순간 전이(transition)로 움직인다**. 12의 "배치 = 확정"이 처음으로 **그림으로** 보인다. **/ 유예**: 히어로 카드 몇 장은 나중에 태그까지 구운 수제본으로 승격 가능(계산본이 기본, 수제가 예외).

**⑤ 생성 규칙 3가지 — 전부 실측으로 얻음** (`scripts/cardart-generate.sh`가 정본):
  - **용도가 아니라 사물을 그린다.** 12 §1이 근거: 의미는 이웃이 만든다. 아트가 한 측면에 시각적으로 커밋하면 "다면성 발견"이라는 재미를 아트가 먼저 죽인다. 실·섬유를 "빗장을 당기는 실"로 그리면 `route` 측면이 미리 확정된다. → 모든 프롬프트에 `no scene, no hands, no action, no narrative`.
  - **바탕을 평평한 근-흑색으로 못박는다.** 안 박으면 모델이 흰 표본 카드를 그리고, **흰 바탕은 어둡게 깎아도 회색 죽이 되어 계산된 처리가 안 먹는다**(1차 시도 실패의 실제 원인 — 재생성으로 해소 확인). 테두리·액자·비네트도 명시 금지(모델이 은근히 내부 보더를 그린다).
  - **조명을 중립으로 둔다.** 극적 키라이트가 구워져 있으면 은밀/공개 처리와 겹쳐 뭉갠다. 조명은 형용사의 몫.

**⑥ 아트 종횡비 = 프레임에 맞춘다(3:4).** 2:3으로 뽑아 92px 가로 플레이트에 넣었더니 인물이 다리만 남게 잘렸다. 카드 프레임 치수가 먼저고 생성 종횡비가 따라간다.

**⑦ 배경 아트 = 신뢰축 장면(3장) × 주목축 컬러 그레이딩(CSS).** 08 §⑤의 3×3=9장을 대체. 엔진 실측: heat·trust는 0~10, `badHeat: 8`, UI가 이미 5·8에서 밴딩한다. 주목(은밀↔공개)은 본질적으로 **광량**이고 신뢰(강압↔신중)는 **장면의 내용**이므로 축마다 성격에 맞는 매체에 실었다. 이미지 9→3이고, 더 중요하게는 **줄다리기가 9개 상태를 점프하지 않고 연속으로 움직인다**(v8 "영향력 가시화"가 장식이 아니라 실제 피드백이 된다). 카드의 ④와 같은 원리 — 명사는 생성, 형용사는 계산.

**⑧ 마켓플레이스 자산 = Higgsfield로 생성하면 호스팅 불필요.** `--thumbnail/--favicon`(deploy)과 `--cover-url/--logo-url`(publish)이 https URL만 받는 건 사실이나, Higgsfield `result_url` 자체가 https CloudFront다. 커버 16:9·아이콘 1:1을 Higgsfield로 뽑아 그 URL을 그대로 되먹인다. **08 §ⓑ가 걸어둔 제약 해소.**

**⑨ 생성기 = Higgsfield CLI `nano_banana_pro`** (2크레딧/장, 3:4, 1k). 스타일 고정은 `--image-references`로 스타일 키 1장을 물린다. **/ 기각**: 로컬 무과금(ComfyUI 미기동 + LoRA/IPAdapter 세팅 비용), 혼합(파이프라인 2개 유지 비용).

### 실측 — 08 §④가 기다리던 숫자 (가정이 틀렸다)

08 §④는 "진짜 코스트는 스타일 일관성을 잡는 반복 횟수"라고 적었다. **틀렸다.** 스타일 키를 `--image-references`로 물리고 성격이 다른 6개 대상 × 2스타일 = 12장을 재시도 없이 1발로 생성한 결과 **스타일 드리프트 0/12**. 스타일은 공짜로 고정된다.

실제 실패 모드는 **대상 가독성**이었다 — 스타일 D에서 6장 중 2장(장부·기차표)이 특징 없는 사각형으로 나왔다. 즉 반복이 필요한 카드는 예측 가능하다(평평한 사각 사물). 스타일 A는 내부 디테일과 음영이 있어 이 실패를 겪지 않는다.

- **장당 예상 시도 ≈ 1.0~1.3회** (08의 가정 4회가 아님)
- 53장 × 1.2 ≈ 64장 ≈ **128크레딧**. 이번 세션 실지출 **54크레딧/27장**, 잔액 1,110 → **1,056**
- **진짜 코스트는 사람 큐레이션 시간** — 53회의 "이거면 됐다" 판단. 생성·크레딧 둘 다 제약이 아니다
